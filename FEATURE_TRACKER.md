# Cosmotune feature tracker

Updated 2026-10-28. This is the central local tracker for features from other apps and original Cosmotune work. A reviewed feature is not automatically implemented; compiled code is not automatically device-tested or released.

**Release status:** releases through [1.0.9](https://github.com/Vijay-Janarthanan/cosmotune/releases/tag/v1.0.9) are published. The [1.0.10 source tag](https://github.com/Vijay-Janarthanan/cosmotune/tree/v1.0.10) adds video recovery/forward-only footage, provider fallback and artist matching, decoder quality labels, film captions and tray/taskbar/Dock controls; its release build is in progress. [1.0.8](docs/releases/1.0.8.md) shipped native Manga/Podio chrome, artwork fallbacks and discovery repairs; [1.0.9](docs/releases/1.0.9.md) shipped the satellite globe, station pages and regional podcast charts. Historical row evidence below retains its original scope and does not certify every device/account check. See [pending work](docs/PENDING_WORK.md) and the [live website inventory](docs/LIVE_WEBSITES.md).

## Status and evidence rules

* **Released**: present in a published Cosmotune release, with a release link.
* **Existing**: present before the current integration; its exact coverage still needs the relevant tests.
* **Implemented**: code and automated checks are complete for every platform the row names and are recorded in the row's evidence; it is not released yet, and any physical-device or account check that remains is listed in the row. Use this only when the evidence supports it.
* **In progress**: implementation exists in the working tree and still has outstanding checks or integration.
* **Planned**: requested/selected, but no complete implementation is claimed.
* **Reviewing**: source/behaviour/dependencies are still being audited.
* **Decision recorded**: an explicit platform or product constraint is documented; this must not be silently treated as completion.

`tools/check-tracker-evidence.py` checks that every Implemented row names at least one test and that each named test class, method, file or test task exists in the repository (its own tests: `tools/test_check_tracker_evidence.py`); it does not show that a test passes, which the build does. Run it after editing a row.

For each named app, inspect source, configuration/settings, tests, packaging and platform-specific modules. Compare the complete feature inventory against Cosmotune, including companion apps. Keep build tests, real-device tests and publication distinct. Record omissions rather than dropping them from the table.

## 1.0.7 release preparation

Version 1.0.7 includes package-source comparison, tappable audio details, regional discovery, local playlist previews, automatic verification callbacks, native media preparation, Windows audio-freeze recovery, Now Playing header dragging on custom desktop frames and the settings creator credit. Local validation passed shared (2,317 reported tests), providers (128), shared UI (662), desktop (474) and UI interactions (61), with Android/TV compilation. Native Windows recovery and Android AAC/24-bit FLAC checks ran separately. Publication still depends on the Release workflow and its signed/packaged artifacts. See [release notes](docs/releases/1.0.7.md), [Windows evidence](docs/WINDOWS_PLAYBACK_FREEZE_2026-10-26.md) and [independent Qobuz comparisons](docs/UPSTREAM_QOBUZ_DOWNLOAD_COMPARISON.md).

The first 1.0.7 Release workflow failed before publication: the provider User-Agent still reported 1.0.6, and an earlier local test result had been reused because external version files were undeclared inputs. Both are corrected. A separate Linux callback assertion was not reproduced in 100 Linux repetitions; full exception/report collection was added, preserving its assertions. The rebuilt 1.0.7 also includes Podio and film-title/publisher/animated-artwork matching repairs. New validation results supplement the earlier counts above; publication remains a separate check.
