# Recommendation model data and changes

Cosmotune's 2026-10-23 model uses source-local listening graphs, separately fitted acoustic neighbours and metadata context. Three graph-diffusion steps are distilled into hashed 32-dimensional int8 embeddings. Duplicate release identities are downweighted. Only a small, balanced name vocabulary is bundled. Raw user identifiers, listening histories, audio, lyrics, artwork and provider URLs are not distributed.

- **ListenBrainz and MusicBrainz / MetaBrainz contributors** — CC0-1.0 listening events and core recording/artist/release metadata. [Datasets](https://metabrainz.org/datasets/postgres-dumps), [MusicBrainz data licence](https://musicbrainz.org/doc/About/Data_License). Retained earlier catalogue metadata contributes context without reusing its later listening weights.
- **Music4All-Onion v2** — Marta Moscati, Emilia Parada-Cabaleiro, Yashar Deldjoo, Eva Zangerle and Markus Schedl. [Publisher deposit](https://zenodo.org/records/15394646), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Derived co-listening links, genre context and separately normalised musicnn features are used. The four-field source-ID/name crosswalk came from [Leon299/music4all](https://huggingface.co/datasets/Leon299/music4all), revision `a391160e3e17f351d5ab2d05439a7d3d7f0440eb`; its authenticity as a publisher-approved mirror has not been independently confirmed. The publisher deposit's licence is recorded separately from that mirror's provenance.
- **Yambda** — Copyright 2025 YANDEX LLC. [Dataset](https://huggingface.co/datasets/yandex/yambda), [publisher LICENSE](https://huggingface.co/datasets/yandex/yambda/blob/main/LICENSE), [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0). Anonymous listen/like/dislike/reversal actions calibrate graph-confidence shrinkage; no anonymous item ID is guessed to name a recording. The dataset card also describes scientific/research use; that wording is retained in the provenance record rather than represented as a separate blanket permission.
- **FMA: A Dataset For Music Analysis** — Michaël Defferrard, Kirell Benzi, Pierre Vandergheynst and Xavier Bresson (2017). [Project](https://github.com/mdeff/fma), [paper](https://arxiv.org/abs/1612.01840), metadata [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Named metadata, genre terms and 32 librosa-derived MFCC statistics contribute source-local context. No audio or Spotify/Echonest feature data is bundled or fitted.
- **Discogs contributors** — [Official data exports](https://data.discogs.com/), CC0-1.0 release/master metadata. Retained entries provide source tracklist and release context, not verified cross-source recording identities or inferred singer/language credits.
- **Wikidata contributors** — [Structured data licence](https://www.wikidata.org/wiki/Wikidata:Licensing), CC0-1.0. Artist genre context joins through exact artist MusicBrainz identifiers; it is not a claim about a song's sung language.
- **Open Opus contributors** — [Data](https://github.com/openopus-org/openopus_api/blob/master/ALLDATA.md), CC0/public-domain data. Full-composer/full-work-title matches provide composition context. A work is not presented as a playable recording.

The full training graph and raw datasets stay outside app resources. The shipped manifest records source counts, temporal source-graph evaluation, compression fidelity and exact model checksums. The compression metric measures agreement with a trained graph, not next-song prediction accuracy. Provider radio/search remains responsible for current candidates and verified playback IDs.
