## Features and boundaries

The browser app has Home/New/search/mood browsing, album/artist/playlist details and pagination, YouTube account/library selection, queues/shuffle/repeat/autoplay/radio, crossfade and playback history, timed/word/background lyrics, video and moving artwork, Spotify library/Canvas and Listen Together. The MV3 helper has Chromium direct messaging and Firefox relay transport, version/protocol detection and package update instructions, explicit account connect/disconnect and optional lyric-host grants. Artist art and motion have separate preferences and network/reduced-motion policies.

The native feature tracker still governs features beyond this browser baseline. Browser sources are not the native provider runtime; no browser `.sflx` installation or direct add-on catalogue is claimed. Native Music/Video/Manga layouts are not replaced by this workspace. Discord remains disabled and is not offered as an integration. The browser player is distinct from the native app's paired LAN remote.

## Adaptations and findings

* Cosmotune names, existing mark, warm accent and system fonts; no old extra font/icon binaries or development key. The newly generated public key pins an independent Chromium ID; no private key was retained. Firefox uses a separate helper identity.
* No assumed production domain, automatic redirect to an upstream site or default hosted party service. Exact helper origins are configured at build time; unset/empty CI values use only localhost. Store builds require HTTPS deployment origins and reject loopback HTTP.
* Background sender checks use exact origins including ports and the browser-provided extension identity for popup/grant pages. An opaque web frame never inherits trust from its URL. Tests cover lookalike hosts, wrong ports, own/foreign extension identities and Firefox extension URL handling.
* Helper metadata reads stream under a 16 MiB decoded-body limit, reject oversized declared lengths, close failed readers and apply request timeouts. Credential-bearing metadata requests reject redirects. Request envelopes bound IDs/methods/parameter size and reject malformed/cyclic data before dispatch. Streaming audio remains in its media transport.
* Browser onboarding text was corrected after a real walkthrough exposed inherited Discord/add-on claims. Missing-helper controls report that dependency. The warm accent uses an explicit contrasting foreground, including focused search options and primary buttons.
* Empty Listen Together configuration fails before contacting the static site; backend addresses reject credential/query/fragment data. The user configures a server or a deployment supplies its public URL. This does not create or schedule a backend.
* Anonymous catalogue fixtures remain test-only. Captured lyric/Spotify documents and upstream design notes were excluded; lyric parser tests use short inline timing fixtures. Existing GPL authorship and imported source hashes remain; packaged notices include installed third-party licence files.

## Evidence and remaining gates

Type checking passes for the app, shared bridge and helpers. **131 tests pass**: 122 player/parser/queue/lyrics/party/render tests, five bridge/HTTP budget tests and four helper origin/sender checks. Production Chromium/Firefox/site builds pass. Archive validation checks versions, identity, permissions, disabled integrations and included notices for 197 installed packages. The refreshed provenance/licence packaging checkpoint measured a 1,333,008-byte static-site ZIP and 125,447/125,193-byte Chromium/Firefox helper ZIPs (`build/upstream/web-package-refreshed-proof.log`). These remain pre-release checkpoints.

A real in-app browser reached Home, Settings and Extension routes with the missing-helper state, correct generated 1.0.4 downloads and the integration instructions. It found the text/contrast issues noted above; the corrected contrast is visually verified. It also exposed an empty-server placeholder crash on the party route; that route now renders correctly, has a real component-render regression, shows required backend configuration and keeps keyboard joining disabled while it is missing. Unexpected routes have a recovery UI rather than a raw implementation stack. Screenshots are saved in `build/upstream/web-extension-runtime.png` and `web-party-runtime.png`. This is not an installed-helper or live signed-in audio test. Chromium/Firefox extension installation, provider account connection, real media decoding, browser autoplay restrictions, sleep/reconnect and party-server round trips remain separate runtime checks. No public domain/site or browser-store package was deployed or published.

CI/release jobs now run the locked workspace install, type checks, tests, both helper builds and `tools/package-web.py`. The release archive is independent of the Android/desktop packages, which continue to use the under-5-MB local recommendation model. Full tracker completion remains required before 1.0.4 is published.
