# Read: books, manga and source audit

Status: Read implementation is published in 1.0.14. The historical research matrix below records source decisions and limitations; it is not a promise that every listed project is integrated.

## Implemented Read experience

Android and desktop route the existing persisted Manga mode to **Read**, with Books and Manga sections. Existing Manga library identities, files, collections and progress are preserved. Manga continues using its chapter/image readers; EPUB/PDF documents have separate owned storage and document engines.

- Books Library supports import, local title/author search, Continue reading, Saved metadata, Downloaded and Finished filters, collections and explicit removal.
- Discover uses attributed Open Library search/trending, Project Gutenberg OPDS metadata and configured personal OPDS feeds. A saved catalogue result is distinct from an acquired file. Broad metadata search includes modern commercial titles without inventing free readable copies.
- EPUB imports parse container, package, manifest, reading order and EPUB3 navigation/EPUB2 NCX. Android WebView and desktop JavaFX WebKit render local XHTML/CSS, supplied colour images and fonts. Scripts and unrequested remote resources are removed. Resource paths, entry counts and expanded size are bounded.
- PDF uses Android PdfRenderer and desktop PDFBox. Colour pages are rendered on demand with page/zoom controls. Text search depends on the platform: desktop and Android 15+ support page search; older Android versions retain reading/page navigation without claiming searchable text.
- Reader controls include contents, chapter navigation, text search, bookmarks, font size/typeface, line spacing, margins, page/scroll controls and light/sepia/dark/system themes. Fixed-layout PDFs retain publisher layout.
- Last position, bookmarks, preferences, finished status and collections use an atomic device-local store. EPUB locators identify resource plus position; PDF locators identify page. Imports use SHA-256 identity and remain available offline.
- Full-file downloads accept only explicitly advertised EPUB/PDF acquisition links. Borrow, purchase, source and sample links retain their source actions. OPDS credentials use the existing platform-protected file store and are scoped to the configured origin.

“Paperback” covers both physical edition metadata and the separate Paperback manga app. The [compatibility review](PAPERBACK_COMPATIBILITY.md) documents its 0.9 extension ABI; Paperback registry execution is not implemented. Colour illustrations require a supplied illustrated digital edition. Physical bindings are metadata, not downloadable formats.

A commercial title such as Harry Potter can be searchable without a free downloadable edition. Source borrowing and purchase terms remain intact; Cosmotune does not bypass them. No universal all-books-free claim is made.

See [release notes](releases/1.0.14.md) and [validation evidence](FEATURE_BATCH_VALIDATION_2026-11-02.md) for the actual checks and platform limits.

## Sources and availability

| Source | Proposed role | Access and implementation decision |
| --- | --- | --- |
| Project Gutenberg | Initial public-domain acquisition catalogue | Use official machine-readable catalogue data and supported OPDS; use approved acquisition links and cache. Do not scrape the website. Recheck destination/territory availability rather than treating U.S. public-domain status as global. |
| Open Library | Broad title/author/ISBN metadata search, covers, real trending discovery, and read/borrow destination links | Search metadata is not permission to download the work. Preserve full access/lendable/checked out/restricted states and edition identity. Begin with source links for borrowing; native borrowing/authentication/DRM requires a separate integration project. |
| Standard Ebooks | Curated public-domain editions and new-release shelf | Public new-release Atom/RSS is accessible; full OPDS/catalogue feeds currently require eligible access, including Patrons Circle credentials. Do not ship it as a universally anonymous full catalogue. Offer optional configured access or import files users already obtained. |
| User OPDS libraries | Implemented configured personal/library catalogues | Support OPDS navigation, search, pagination, acquisition relation and MIME types; handle authentication/expiry explicitly and retain provenance. Implement OPDS 1.2 and 2.0 adapters behind one normalized model. |
| Local EPUB/PDF/CBZ | Implemented offline reading and user-owned library | EPUB and PDF use separate document engines. Reuse existing CBZ/image-folder import for Manga. Never coerce EPUB or PDF into Manga image chapters. |

Project Gutenberg documents OPDS and machine-readable metadata, and says its XML OPDS feed is expected to sunset in 2027 while OPDS2 access is currently being tested; keep catalogue transport replaceable. Its robot policy specifically directs automated catalogue access to machine-readable data. [Catalogue formats](https://www.gutenberg.org/ebooks/offline_catalogs.html), [robot access policy](https://www.gutenberg.org/policy/robot_access.html).

Open Library supports broad search and edition availability lookup. API clients should identify themselves, cache and respect request limits; it is not a bulk or high-traffic backend. [Search API](https://openlibrary.org/dev/docs/api/search), [Read API and access statuses](https://openlibrary.org/dev/docs/api/read), [API usage policy](https://openlibrary.org/developers/api).

Standard Ebooks documents the feed access distinction and OPDS 2.0 content negotiation. The public new-release Atom feed supplies the latest fifteen releases, not its whole catalogue. [Feed access](https://standardebooks.org/feeds), [Atom feeds](https://standardebooks.org/feeds/atom).

## Truthful discovery

“Trending on Open Library” should use Open Library's actual trending sort/signals, preserve provider order, and show the retrieval time. Its documented algorithm measures recent changes in activity using page views and reading-log events; it is not a universal bestseller list. Filter readable availability as a separate user choice. [Trending algorithm and search fields](https://blog.openlibrary.org/2025/08/06/whats-trending-on-open-library/).

Do not call alphabetical results, a static classics list, or random covers “Trending.” If a provider does not supply a ranking, label the shelf New releases, Popular on that provider only when supported, or Browse. On network failure, show cached content with its age and a Retry action; never fill the shelf with invented popularity figures.

## Architecture

1. Introduce a reading domain next to the existing Manga module: `Publication` with stable work/edition identifiers, content kind, format, metadata, source, rights/access state, and zero or more acquisition links. Avoid renaming `MangaBook` globally in the first increment.
2. Separate `BookCatalogue` (search/discover/availability) from `PublicationImporter`, owned-file storage, and `ReaderEngine`. A saved metadata entry does not require downloading its contents.
3. Define reader-neutral locators: EPUB resource href + progression/text anchor; PDF page + viewport; CBZ chapter/page + offset. Store publication file hash/edition identity with a locator. A percentage alone is insufficient after reflow or edition changes.
4. Reuse the existing atomic persistence, collection, download, and backup patterns where appropriate; add a versioned books store and explicit migration. Do not change or delete existing Manga library files during the first release. Preserve all existing progress/downloads when the mode is eventually renamed.
5. A bookmark is a named saved locator (with optional note/quote) and must be separate from last-read position. Autosave current position at sensible intervals and on leaving the reader. Keep bookmarks after reflow, restart, offline use and catalogue removal.
6. EPUB requires a real document renderer: spine/navigation, CSS/reflow, fonts, internal links, accessibility and locator restoration. Spike Readium Kotlin on Android and a desktop-compatible EPUB engine separately before selecting dependencies. Readium Web currently documents EPUB support while PDF/comics are future work; it is not a drop-in Compose Multiplatform reader. Keep UI and persistence shared behind host adapters. [Readium Kotlin](https://readium.org/kotlin-toolkit/), [Readium Web scope](https://readium.org/web/).
7. OPDS is a distribution/discovery protocol, not a rendering engine or authorization shortcut. Preserve acquisition relations, MIME types, authentication and pagination. [OPDS 2.0 specification](https://specs.opds.io/opds-2.0.html).
8. Apply existing archive limits/path validation to EPUB imports; prevent active scripts and unrequested remote loads, bound downloads, preserve source credentials in protected storage, and cancel cleanly. File removal and “remove from library” must remain explicit separate actions.

## Delivery sequence and acceptance

1. Reader feasibility: prove one public-domain EPUB imports and restores a durable locator on Android and desktop. Check reflow at large text, internal links, accessibility, and packaging. Choose engine/dependency/licensing only after this proof.
2. Offline Books MVP: EPUB import, metadata/cover, library search and collections, reader preferences, autosave, bookmark create/jump/delete, and backup/restore. Tests use small checked-in or generated public-domain fixtures, not network dependencies.
3. Catalogue discovery: Project Gutenberg supported metadata/OPDS acquisition; Open Library search/covers, attributed trending, and explicit access states. Provide cached/retry/offline and no-results states. Implement throttling and a proper app contact user-agent before broad API usage.
4. PDF and optional OPDS: add host renderer adapters, page bookmarks and keyboard/touch parity; authenticated user OPDS and Standard Ebooks access only with proper configuration. Borrowing remains a source handoff until separately implemented.
5. Naming/navigation migration: once both hosts can read books reliably, rename Manga mode to Read, add Books/Manga filters, migrate user navigation preference, and verify existing Manga progress/downloads/collections remain identical.

Acceptance must cover offline EPUB reading; bookmark survival after font changes/restart; correct edition matching; search metadata with no readable copy; checked-out/restricted/borrow-only results; missing covers; partial provider failures; cancelled import/download; corrupt/oversized archives; narrow Android layout and desktop keyboard reading. Never mark a feature complete solely because metadata appears in a grid.

## Manga changes implemented now

- Library keeps Import comic and a Settings menu. Manage sources and Image folder are in that menu; the redundant provider picker is absent from Library, and detail pages do not carry setup/import controls.
- Discover immediately browses the first enabled source. On first discovery with no configured sources, it considers the pinned official MANGA Plus English catalogue once. This decision is persisted, including when the catalogue is unavailable; explicitly removing the last source keeps it removed across restart. Catalogue lookup and persistence run on IO. Existing configured subscriptions migrate to setup-considered, and disabled sources stay disabled. Typing searches all enabled sources; choosing an individual source remains available for advanced browsing/language selection.
- Empty Library offers Discover manga; no-enabled-source discovery offers Manage sources; failed catalogues expose Retry. Source failures and website verification remain visible and recoverable.
- A single source policy excludes source identifiers, display names and extension package identities containing `hent`, case-insensitively after Unicode normalization and separator removal. Kotatsu listings and extension stores hide excluded entries (including nested modern store source names). Configuration, APK review/download/trust/install, repository access and global search enforce the same policy.
- Existing blocked subscriptions disappear on load and subsequent writes; their active reader navigation clears. Saved series, collections, bookmarks/progress and offline page files are retained. The filter is exactly a requested source-name rule, not a comprehensive content-rating classifier.
- Shared `MangaApp` and persistence apply to Android and desktop; no host navigation entry changes are needed. JVM fixtures cover normalized names, restore/migration, rejected use/install, store filtering and global search. UI fixtures cover immediate discovery, disabled-source management, and menu reachability at large text. Root task owns batched Gradle validation; this subtask did not run Gradle or commit.

## Expanded research: modern books and open-source library projects

The user's follow-up requests coverage beyond free classics. The viable result is a union of broad modern-book metadata, individually available copies, and the user's own library services. Open-source applications can manage or locate commercial titles, but their software license does not grant access to every book those applications can name. The following distinctions determine adapters and labels rather than excluding commercial titles from search.

Native support for licensed loan/protected formats would require a separate supported entitlement/DRM integration, while personal unprotected EPUB/PDF copies can use the implemented file-reader path. [Calibre format/DRM FAQ](https://manual.calibre-ebook.com/faq.html).

### Adapter checkpoint implemented in this workspace

The original metadata foundation now sits under the implemented `reading.data` domain. `ReadingRepository` handles owned imports/acquisitions and atomic library state; `ReadingEpub` parses bounded packages; platform `ReadingDocumentView` adapters render documents. Open Library adds a bounded cache and request pacing; OPDS search expands advertised templates or same-origin OpenSearch descriptors. Local HTTP/archive/rendering fixtures and native/live opt-in probes cover these boundaries.

No live personal BookOrbit/Calibre/Kavita instance was connected because no endpoint/account was supplied. Named-server compatibility is based on documented OPDS and local fixtures. Native borrowing/DRM, automatic cross-catalogue edition matching, remote progress synchronization, Google Books API integration and Paperback 0.9 execution remain outside the implemented reader scope. Physical Android reading and interactive macOS/Linux reader checks remain separate validation tasks.
