# Upstream review — 28 October 2026

This review checks 20 external repositories plus the owned OpenCanvas engine. Default-branch heads and published releases were queried separately. The review used pinned commit comparisons, repository trees, release/changelog material and 56 selected source/licence files. It is a feature and integration review, not execution of every upstream app or a claim of complete feature parity. Historical import pins remain unchanged until a corresponding integration is verified.

The [implementation follow-up](UPSTREAM_IMPLEMENTATION_2026-10-28.md) records the subsequent recording-based matcher, Gilli fix and compatible feature/bug-fix integrations. Its work supersedes the original one-singer alias approach for JioSaavn; this review's tables preserve the findings at the time they were inspected.

### Other provider results and limits

- The installed **Amazon 2.3.14**, **YouTube Music 2.4.4** and **Tidal 1.2.9** package hashes match the inspected current registry. A package reinstall alone is not an established repair.
- YouTube Music's package returned `api_error` for both Ayyo Ayyo and Aathi. The working native YouTube fallback is a distinct path. The error's underlying cause remains unresolved; it has not been attributed conclusively to the host or upstream service.
- The Tidal Aathi stream request exceeded the diagnostic's 45-second limit. Its first 15 bare-title Ayyo results did not include the required singer; this is not a catalogue-wide absence claim.
- A resolved FLAC URL/offer is not proof of decoder success. Aathi's Amazon probe went through the actual native decoder; the new race regression itself uses deterministic fixture requests. Interactive handover on the installed app still requires a build containing these changes.
- The new repair is after 1.0.10. Existing 1.0.10 installers do not acquire it when source or website documentation is updated.

## Priorities after this repair

1. Build and interactively verify the source-upgrade, JioSaavn credit, source-status and video repairs. Preserve recording checks and working audio during failed upgrades.
2. Diagnose current YouTube package extraction and provider-specific Amazon/Tidal failures independently; use actual decoding results rather than a catalogue match or offered tier.
3. Design output negotiation explicitly: LastWave's Windows exclusive implementation is a reference, while macOS needs a separate higher-precision backend/fallback investigation. Cosmotune currently defaults to 16-bit PCM unless changed in Settings.
4. Audit BitChord's cache/uploaded-song/telemetry and browser Automix/menu deltas against the current Cosmotune implementations.
5. Expand statistics and public podcast discovery; plan Lokal-style desktop/mobile library synchronization separately from the existing remote control.
6. Compare Manga extension-repository deletion, replacement rollback and cache expiry against Tsuki/Mihon regressions.

The 3.19 MB recommendation model was not retrained or replaced by this audit. No recurring update job, additional app release tag or provider account was created.
