# Provider packages

Android and desktop now share a `providers` module for Mornye/SpotiFLAC `.sflx` and `.spotiflac-ext` ZIP packages. This is separate from Cosmotune's existing HTTP JSON add-ons. The published v1.0.6 contains package management and a partial runtime. The current development follow-up is documented in [provider capabilities](PROVIDER_CAPABILITIES.md) and the [Amazon resolution investigation](AMAZON_RESOLUTION_INVESTIGATION.md). The full [feature tracker](../FEATURE_TRACKER.md) remains the release gate.

## Working paths

Sources → Provider packages opens repository/import management on both platforms. Importing first reads metadata and computes a SHA-256 digest without executing JavaScript. The package review shows identity, version and requested access. Trusting installs the exact reviewed archive; repository downloads must also match the listing's hash, identity and version. Updates preserve disabled state and settings, and reject downgrades. Importing a repository does not trust its packages automatically.

Enabled providers can search, load album/artist/playlist pages and browse cached regional home sections. The browser uses Cosmotune song rows and passes source-qualified recording IDs into the native queue. Android's Addons search also includes enabled package providers. Feed caches include provider code, settings, region and language; a failed refresh can retain the previous feed. The same regional sections now supplement the main native Home page on Android and desktop. Source cards preserve full recording metadata; feeds use configured region/language, are independently cached and cannot hide another source on failure. Broader account discovery is still outstanding.

Providers exposing `getDownloadUrl` can supply audio to both native players and download paths. An ephemeral loopback relay carries bytes and seeks while the remote requests retain provider domain, DNS, redirect and credential checks. Remote signed URLs and headers are not handed to the decoder. Android permits cleartext only for the `127.0.0.1` relay; external cleartext remains disabled by its network security configuration. Disabling, replacing or removing a provider revokes its media leases. Provider declarations remain distinct from actual decoder codec/bitrate reporting. A selected provider recording is not silently downloaded from YouTube on provider failure.

The file permission grants only a private workspace. It supports bounded text/binary slices, writes, copy/move/delete and whole-file network downloads. Transfers use strong ETags or Last-Modified validators, exact Content-Range/length checks, URL-hash checkpoints and atomic publication. Invalid or changed ranges cannot append another recording. Chunked bodies have byte limits, and incomplete output cannot replace a completed file. Workspaces have entry and byte quotas. Transform, segmented-download and FFmpeg APIs are not yet complete and fail explicitly.

## Boundaries and limits

* Packages: 32 MiB compressed, 64 MiB expanded, 100 entries; metadata 256 KiB and script 8 MiB. Paths, duplicate entries and UTF-8 are checked.
* Metadata: 2 MiB including decoded/chunked bodies. Network domains must be declared; private addresses require the provider's local-network option. Redirects cannot downgrade HTTPS or forward custom credentials to another origin. Cookies are provider-local and bounded. Session cookies survive VM retirement within the current app; only persistent cookies are protected on disk. Disconnect rejects cookies arriving from earlier requests.
* Code: Android QuickJS reuses the existing runtime with a 64 MiB guest memory limit and evaluation deadlines. Desktop Graal denies Java class access, native access and guest threads, with statement/time limits; it has no isolated per-context heap quota. At most two runtimes run concurrently. Cancellation releases host IO and joins the VM worker before reuse.
* Storage: provider state is capped at 4 MiB. Android uses Keystore encryption, Windows uses current-user DPAPI, and macOS/Linux use owner-only filesystem permissions. Unreadable state is preserved and blocks replacement. Android automatic backup/device-transfer rules now exclude provider and manga files, including offline media. Portable export/recovery remains part of the backup work.
* Media: up to four relay workers, bounded requests/leases and 512 MiB per response/file; only loopback listeners are opened. This relay is not reachable by Cast receivers or a watch and needs explicit output integration before claiming those paths work.
* Artwork: native Coil loaders now resolve opaque source references through a checked transport. No raw signed cover address enters saved song metadata. Static JPEG/PNG/WebP headers are checked before decoding (8 MiB encoded, 8,192 px per side, 40 million pixels); animated/SVG formats are refused on this path. Up to four fetches run concurrently; the disposable image cache is bounded to 128 MiB/512 files with a 24-hour fresh period, and its bounded reference index is protected like provider state. Existing covers work offline. Packages have a separate public-artwork download option; local hosts still require declared-domain/local-network access. HTTP add-ons can use their configured origin, with cross-origin credentials and arbitrary private addresses excluded. Android external cleartext artwork remains blocked by its network-security policy; the internal loopback exception does not enable arbitrary cleartext servers.

Supported required-runtime declarations now include `preparedContext@1`, `signedSession@1` through `@3`, `sessionGrant@1` and bounded `patternedFileTransform@1`. Other requirements still fail before evaluating the package. Operator sessions and app-owned callback routing have controlled native/runtime coverage. Ordered segmented-file transfers now have controlled transport/SDK checks. File-only playback and native MOV preparation/SDK inspection are implemented below; manifest-aware HLS/DASH relaying, encoding beyond stream copy and final provider walkthroughs remain outstanding. Supported PKCE loopback callbacks now return automatically from an explicitly opened browser sign-in. Packages are not claimed fully compatible merely because their manifests import. A working JioSaavn AAC test establishes no lossless-provider or DAC-fidelity claim.

## Provider sign-in and cipher utilities

Packages with storage and network grants can keep their own tokens, request a browser sign-in, generate S256 PKCE and exchange a code over their declared HTTPS transport. Sources shows the pending sign-in and retains a masked manual callback field. Open sign-in page first binds eligible HTTP loopback callbacks to their exact configured IPv4/IPv6 interface and unprivileged port; `localhost` compatibility still binds only loopback. The listener is tied to the installed provider/hash and pending proof: ten minutes for PKCE and three minutes for operator grants. Busy/unsupported callback addresses retain manual recovery. Opening the browser does not start a LAN server or transfer native YouTube/Spotify credentials.

The callback must match its address, unique random state and lifetime, and is accepted once. Root HTTP paths and host case normalize without allowing another port. Listener headers are capped at 24 KiB, request targets at 16 KiB and completion at 25 seconds, including the operator exchange; at most four providers can wait. Disable/remove/settings/update/disconnect/shutdown revoke listeners. A failed browser launch or cancelled handoff releases its lease. The static result page echoes no code/state, disables caching/referrers and removes query data with a CSP-hashed script. A provider's sign-in/check action completes token exchange after the code arrives. SDK `authUrl`/`pkce` result fields are retained alongside the native `open_auth_url` handoff.

Android phone and TV now register their own package-ID callback schemes, with separate legacy `cosmotune`/`cosmotune-tv` aliases. Incoming links must match one pending random proof and its complete address; the Activity clears the callback URI before music/share routing. TV uses its own default grant callback. Desktop keeps loopback and manual recovery until an OS scheme is actually registered. Arbitrary third-party callback schemes are not registered or intercepted. Disconnect clears scoped tokens/cookies, retires runtime/media and cannot be undone by an older token/cookie response. Storage grants remain required; native disconnect also works after an update removes that grant. The loopback/browser/PKCE design follows the [native-app OAuth guidance](https://www.rfc-editor.org/rfc/rfc8252#section-7.3); this implementation does not assume an external provider has registered Cosmotune's callback or supports its requested flow.

Cipher helpers now support the SDK's SHA256-password/AES-256-GCM text wire format and bounded AES CBC/CTR block/segment operations through platform cryptography. Payloads are limited to 256 KiB; segment counts and aggregate work are bounded. They cannot decrypt the app's own credential files. Blowfish is offered only where the platform JCE implementation supports the requested transform; no cross-platform Blowfish claim has been verified. Bounded patterned file transforms now have separate checks below; segmented file transfers, FFmpeg and full provider walkthroughs remain outstanding.

Seven authentication checks cover the RFC 7636 proof vector, SDK response fields, HTTPS token exchange, callback/state/expiry/replay validation, reserved parameters, canonical HTTP callbacks and disconnect races. Five loopback checks exercise real sockets for one-use delivery, wrong routes/hosts/proofs, duplicate parameters/body rejection, expiry, stalled/in-flight cancellation, listener budgets and busy/unsupported-address fallback. Four actual Compose interactions cover manual rejection/recovery, automatic callback completion without pasting, failed-browser lease cleanup and disconnect after losing storage permission. The focused provider suite completed **65 tests, zero failures/errors, one skipped opt-in case**, and these four interactions plus Android/desktop compilation passed in 2m03s. This is separate from the previous 5,076-test full native checkpoint.

Four cipher tests cover NIST AES CBC/CTR vectors, independent Node-compatible GCM bytes, tampering, budgets and guest calls. Three real-HTTP/cookie tests cover persistent reopening, session lifetime, package/path/secure isolation, quotas and stale-cookie rejection. Android emulator execution passed cipher vectors, UTF-8 GCM compatibility, PKCE and encrypted-token reopening; a later emulator check passed protected persistent cookies/plaintext-absence assertions. Those earlier callback checks were JVM/native-UI fixtures; the later real Android Activity and operator-state checks are recorded below. Real external provider-account verification remains separate.

## Operator sessions and file processing checkpoint

The shared host implements operator bootstrap, verification challenges/grants, HMAC-SHA256 signed requests, expiry/renewal, one fresh session retry and at most two provider-declared same-operation retries. Signatures match an independently generated pinned Lokal/Node vector, including escaped paths, the body digest, millisecond UTC timestamp and rotating key. Nonces are fresh 16-byte hexadecimal values. Signing and exchanges are restricted to the declared HTTPS origin and base path, with redirects disabled. The package cannot replace protected signature headers. Namespace/configuration, installation generation and provider identity isolate persisted records; native disconnect prevents an in-flight response from restoring them.

The operator, rather than this app, decides whether to issue a session or verification grant. There is no shared operator account, bundled key or implicit access to a subscription. Supplied callback configurations remain subject to provider registration; manual recovery supports callbacks this app does not own. The SDK exposes status/clear/grant completion and signed fetch only for configured providers. Current native callbacks exchange signed grants immediately; failed exchanges retain an explicit retry. Ordinary OAuth keeps its provider-specific exchange. Expired sessions retain native disconnect access. See [current verification windows and live proof](PROVIDER_VERIFICATION_BROWSER.md).

The focused operator checkpoint passed **80 provider tests, zero failures/errors, one opt-in skip**, plus **five native sign-in UI checks**. Android, TV and desktop compile (`provider-signed-session-expanded-fixed-validation.log`, 2m42s). The Android emulator separately passed three QuickJS/Keystore/cipher tests: encrypted operator-session reopening, no secret in guest status/plain disk bytes, native disconnect, the independent signing vector and Blowfish CBC/CTR round trips. The preceding real Android Activity routing test also passed, with no Android runtime errors. Neither checkpoint used an external operator account or real verification grant.

Patterned transforms now process selected CBC/CTR segments in bounded buffers, restart the IV for each selected segment, retain skipped/tail bytes and stage output before atomic publication. Four new tests pass known vectors, round-trip/in-place operation, cancellation, invalid partial blocks and quota/segment limits. The file API limits a segment to 256 KiB and a file to 512 MiB within the existing 1 GiB private workspace. The native file API and progress/status UI now compile on phone, TV and desktop; file-only playback and the next combined native regression remain in progress. This is not a claim that every upstream provider or file/FFmpeg API is complete.

## File workers, segmented transfers and revocation

Long file operations use a bounded two-worker/four-waiter host queue. The VM polls owned job tokens and invokes progress functions on its own thread; native code never re-enters an active QuickJS callback. Event queues retain at most sixteen progress snapshots, callbacks are released after use and invocation boundaries reset their registry. This follows the [QuickJS integration guidance](https://github.com/dokar3/quickjs-kt#modules); the installed 1.0.14 artifact was also inspected. Five JVM checks passed real throttled HTTPS intermediate progress, callback-driven cancellation, previous-file preservation, bounded queues and job ownership.

Segmented downloads stream ordered input into one staged file without buffering a second complete copy. Up to 4,096 declared-host segments, 512 MiB aggregate output and the private workspace quota apply. Segment ranges must exactly match Content-Range/length, encoded or HTML/JSON responses fail, retries roll back a partial segment, and failures keep the old destination. Concurrency options are accepted as scheduling hints; this ordered path uses one media stream. Six real HTTP/SDK checks passed ordering, headers/chunking, ranges, retry/cancellation, byte limits, staging cleanup and four-argument segment progress.

Native Sources now displays throttled operation status and bounded progress. Ten targeted Compose interactions pass, including showing/removing real runtime status and disconnecting an expired operator session. Disabling a provider now revokes live and initializing host work before waiting on its operation lock, and stale initialization cannot publish a runtime or media lease. Two lifecycle checks pass blocked-read/startup cancellation and a subsequent re-enable/update.

Media lease revocation now closes the associated local reader sockets as well as upstream calls. A real four-reader backpressure test confirms all four relay workers are freed for another stream. Accepted connections have a ten-second header deadline and the existing five-minute media lifetime now closes local writes too; cancelled timers are removed. The response is non-sniffable and cannot execute provider HTML. This fixes a blocked-write lifecycle gap; it does not implement manifest-aware HLS/DASH or remote-device relaying.

This checkpoint passed **98 provider tests, zero failures/errors and one opt-in skip**, plus **ten targeted UI tests**. Android/TV/desktop compilation and the provider instrumentation APK passed in 2m53s (`provider-file-progress-native-validation.log`). The Android emulator then passed all three provider fixtures, including the real QuickJS worker/poll/callback route, patterned AES file bytes, protected session/cookies and cipher vectors, with an empty runtime error log. The following combined checkpoint passed 5,120 native tests, zero failures/errors and thirteen skips across all ten modules in 3m33s (`provider-progress-full-regression-counts.json`). Later file-only playback work remains separate.

## File-only playback and repository listings (cx-p1)

Packages that implement the SDK's `download(trackId, quality, outputPath)` instead of `getDownloadUrl` can now play on both hosts. The host passes a path inside a locked, disposable directory of the provider workspace; the returned `file_path` must be a complete regular file inside that workspace (512 MiB at most), and its container is read from its bytes rather than its suffix. The loopback relay serves a leased copy with byte ranges, the same no-store/nosniff/sandbox headers as relayed media, and never exposes the workspace path. Disabling, removing or updating the provider, lease expiry, eviction and shutdown close the lease and delete the copy. Two `ProviderPreparedStreamTest` checks cover ranges, labelling, refusal of other recordings, the missing file permission and cleanup on disable. Manifest-aware HLS/DASH relaying remains unavailable and fails explicitly. Native MOV preparation and the bounded FFmpeg inspection/stream-copy API were subsequently implemented; see [preparation and decoder evidence](PROVIDER_MEDIA_PREPARATION.md).

Repository listings now say whether a package is new, a real update (a newer version, or the same version republished with different bytes), already installed or older than the installed one; only the first two can be downloaded for review. Downloaded packages are checked against the listed hash, identity and version, rejected downloads leave nothing staged, and a redirect cannot downgrade to HTTP (`ProviderRepositoriesTest`, 3).
