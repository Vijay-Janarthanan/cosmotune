# Manga upstream integration — 28 October 2026

This pass applies the relevant source-lifecycle and cache behavior from the Tsuki/Mihon review to Cosmotune's shared Manga repository. It is an original implementation around the existing parser and Android APK bridges, rather than a replacement with either upstream app.

| Reviewed behavior | Cosmotune change | Evidence |
| --- | --- | --- |
| Tsuki: avoid duplicate catalogue requests | Concurrent requests for the same source configuration, search and page share one request. At most 32 completed catalogue answers are retained for 60 seconds. Search text, pagination, language/source settings and source invalidation have distinct cache identities. Failures are not cached. | `MangaSourceLifecycleTest.catalogueRequestsAreSharedButLanguagePaginationAndExpiryStayIndependent`, `MangaRequestCacheTest` |
| Tsuki: honor removed repositories/sources | Saved repository removal already persisted without a default subscription being reinserted. Central save/remove methods now guard publisher changes, and a regression checks restart behavior. Removing a subscription preserves already trusted installed APK sources. | `deletedStoreSubscriptionsRemainDeletedWithoutRemovingInstalledExtensions`, `aRemovedSourceCannotReturnItsLateCatalogueOrReappearOnRestart` |

Completed offline downloads and active download pins remain protected from expiry and clear-cache. The changes are shared by Android and desktop where the source type is supported. Android APK extensions remain Android-only. The request caches are in memory, so page URLs and request headers are not newly persisted to disk.

MG-08 now includes an explicit browser handoff. A failed catalogue or chapter offers source verification; Manga sources also has a website-verification selector with reset. Android 9+ opens a non-exported Activity in `:mangaverification`, with a dedicated WebView data suffix, no native JavaScript bridge, no access to music account cookies, and backup exclusions for its temporary browser profile. The user completes the check and chooses **Use verified session**. Android 8 reports the isolation requirement instead of sharing another WebView profile.

Desktop uses an installed Chrome, Edge or Chromium in a new private temporary profile, with its own loopback-only CDP connection. It does not reuse the user's normal browser profile or add a browser bundle. The user completes the check, then confirms in Cosmotune. The owned window/profile are cleaned up on completion, cancellation, request expiry or app shutdown. A missing supported browser produces an actionable error.

The handoff validates a request nonce, expiry, source configuration and exact HTTPS origin. Cookies and the actual browser user agent live only in RAM for at most 30 minutes. They are applied only on that exact origin, including redirect hops; late replies after reset/expiry cannot persist proof into the Manga cookie file. Accepted sessions invalidate catalogue/page-list identities so retry uses the new session. Source settings changes invalidate the proof. There is no human-check automation, clearance service or bypass. A website can reject a WebView or a cookie reused by the HTTP client; arbitrary source sign-in and browser compatibility are not promised. Hidden-page request capture and WebView-only parser engines remain unsupported.

The additional 1.0.11 integration adds named collections with create/rename/delete, multiple collection membership, library and unassigned filters. Deleting a collection preserves its series and reading history. Older library files default to no collections. Portable JSON metadata backups merge online series, reading history and collections while preserving existing series/progress; they omit source configuration/credentials, browser proof, local archive paths and downloaded pages. Reimporting the same local comic before restore allows its collection membership to return.

Chapter updates now support an optional daily or weekly interval, defaulting to **Off**. Manual checks remain available. Android uses unique WorkManager periodic work requiring a network connection and adequate battery, with a shared repository to avoid racing separate mutable stores. Desktop checks due libraries while the app is open. Each run remains bounded to three concurrent series, 60 seconds per series and eight minutes overall; failures remain per-series, saved chapters are marked new, and no chapters are automatically downloaded. This does not schedule recommendation-dataset refreshes.

Archive import adds CBT/TAR and gzip-compressed TAR (`.tar.gz`, `.tgz`) by streaming them into the existing CBZ storage. No native/archive decoder bundle is added. Conversion checks TAR checksums, names, duplicate entries, entry types, image sizes, total expanded bytes and cancellation. Links, special files and extended/PAX/GNU headers are rejected rather than interpreted. RAR/CBR, 7z/CB7 and PDF still need conversion to CBZ; supporting them would require additional decoders and an explicit app-size decision.

The Manga controls now use the existing app language selection on Android and the DesktopStrings catalogue on desktop. Fifty control labels are translated into Hindi, Tamil, Telugu, Kannada, Malayalam, Bengali, Marathi, Gujarati, Punjabi and Odia, alongside English. Source-editor explanations, technical status/error messages and untranslated text fall back to English. This is control-label localization, not a claim that every technical Manga sentence has been translated or linguistically reviewed.

Remaining work includes broader real APK/parser compatibility, full technical-copy translation review, additional archive decoders and physical-device/accessibility/low-memory testing. Real verification sites and physical Android/macOS/Linux browser sessions still need manual validation; offline protocol tests do not establish their compatibility. Android background scheduling also needs an actual device run under OS battery restrictions.
