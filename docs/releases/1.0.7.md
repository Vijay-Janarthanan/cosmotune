# Cosmotune 1.0.7

## Playback and audio details

- Fix a Windows playback freeze where the UI waited for the audio-output lock. Invalidated WASAPI clients are recreated even when the device ID stays the same; stalled retries and paused writes/drains are bounded. Device labels are cached and output-device enumeration runs outside the UI thread.
- Restore window dragging from the Now Playing header and its empty top margin on custom desktop frames, in both player looks. Buttons retain their own click targets, and fullscreen keeps its existing behaviour.
- Enabled audio provider packages participate in recording matching and quality comparisons on Android and desktop. Metadata-only sources stay out of audio selection. Existing title, artist, edition, album and duration checks apply.
- Tap the new player's format line to open Audio details: playing source, measured decoder input, provider declarations, attempted sources and advertised package tiers. The existing output/DSP panel remains available from there.
- Process provider-supplied MOV decryption keys and stream-copy remuxing through the bundled desktop/Android libraries. This preserves the encoded audio without resampling or lossy re-encoding. Add SDK file inspection and stream-copy compatibility calls.
- Keep E-AC-3 separate from verified JOC/Atmos metadata. A provider's Dolby badge does not establish immersive speaker/headphone output.

## Verification and discovery

- Provider verification can complete in a dedicated desktop Chromium window or Android verification Activity, capture the callback, exchange the grant and save the session automatically. System-browser/manual recovery remains available.
- Preserve operation ticket headers alongside signed-session headers. Give signed download-preparation requests and complete-file provider downloads bounded, appropriate deadlines.
- Home adds independent country/global charts and preferred music-language controls. Supported provider feeds receive the selected locale; language discovery is labelled separately from popularity charts.
- Make my playlist previews suggestions using the existing tiny local model, listening preferences and available recordings, then saves an editable local playlist. No additional large recommendation model or hosted training service is included.
- Settings includes “Made with love by Vijay” above the version and project links.

## Verified behaviour and remaining limits

- OpenCanvas preserves film context from catalogue titles, rejects unverified fan-channel fallbacks, animated posters and full-film results, and retries bounded alternatives after a soundtrack mismatch. Old automatic choices are rechecked under selection policy 3.
- Live tests aligned film clips for **Nilaave Vaa** and **Andhi Mazhai**. **Germaniyin Senthen Malare** no longer treats the animated artwork upload as a film video; the tested remaster did not align reliably with the stereo recording, so this case keeps its cover.

- Amazon's reviewed package resolved **Blinding Lights — The Weeknd** and passed actual Windows decoding as **24-bit FLAC at 44.1 kHz**.
- Android emulator tests passed CENC AAC and 24-bit FLAC preparation with original-packet comparisons, plus cancellation, wrong-key and quota checks. All three shipped Android native ABIs were rebuilt.
- Qobuz package search and verification worked, but its download endpoint returned HTTP 503 twice in Cosmotune's live check. The same package/session/song also failed in Lokal's unmodified host (three thirty-second stalls) and Mornye 5.2.6's published native extension engine (a 120-second timeout). These backend checks do not establish that every Qobuz service or recording is unavailable. The separately tested Qobuz HTTP add-on is a different route. [Comparison details](../UPSTREAM_QOBUZ_DOWNLOAD_COMPARISON.md).
- Package HLS/DASH relaying, encoding beyond stream copy, additional post-processing hooks, physical Android provider walkthroughs, macOS/Linux real-account checks and immersive output verification remain pending. Complete-file provider playback waits for delivery and preparation.

See [provider evidence](../PROVIDER_MEDIA_PREPARATION.md), [Windows freeze investigation](../WINDOWS_PLAYBACK_FREEZE_2026-10-26.md) and [remaining work](../PENDING_WORK.md).

## Podio: radio and podcasts

- Add Podio beside the existing modes on Android phone/tablet and desktop, with Radio and Podcasts sections. Radio Browser powers a draggable/zoomable station globe, name/country/language search and local favourites; Natural Earth supplies the public-domain map.
- Discover shows through Apple/iTunes and fyyd and open publisher RSS/Atom feeds. Spotify show/episode links use anonymous metadata, adapted from Votify, to find matching public publisher RSS audio. Direct Spotify-only/protected audio is unsupported; no listener account, Python runtime or extra backend is required.
- Follow shows, resume episodes, seek/back 15 seconds and change playback speed. Use the existing Android background service or native desktop decoder. Music scrobbling, beat analysis and music-video discovery skip radio and podcast items.
- Actual desktop decoding passed for radio and publisher RSS MP3. Spotify links are verified separately as metadata-to-publisher-feed matches, not as a direct Spotify audio service. Opening clear bytes did not prove full Spotify playback; late-seek tests failed, and that experimental resolver was removed. Source availability and Spotify metadata web-client changes can affect lookup.
- The globe samples 1,200 popular geolocated stations; list searches return up to 100. Feeds load up to 1,000 episodes and Spotify shows load their latest 100. Archive pagination, downloads, OPML, sleep timers, TV/Wear/browser Podio interfaces and physical-device walkthroughs remain pending. [Research and evidence](../PODIO_RESEARCH.md).

## Release repairs

- Fix the provider runtime User-Agent version pin that failed the original desktop release tests. Declare the external version files as test inputs so Gradle cannot reuse a stale version-pin result.
- Keep complete exception output and upload failed Linux/shared desktop test reports for useful CI diagnostics. The Linux callback test passed 100 isolated Linux repetitions; a single original CI failure remains unreproduced rather than being hidden by weakening its assertions.

Final local checks passed: shared JVM (2,330 reported tests), providers (128), shared UI (662), desktop (476), UI interactions (63), Android prod-debug unit tests (1,180), phone/test APK assembly and TV compilation. Two Android emulator tests passed real publisher playback and seeking, including a feed matched from a Spotify link. OpenCanvas's separate JVM/JavaScript checks and upstream CI passed; its import hashes and Android model resources were verified. Opt-in/network/hardware skips remain distinct from these results.
