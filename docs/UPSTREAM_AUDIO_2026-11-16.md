# Audio/provider integration evidence — 16 November 2026

Scope: release 1.0.24 implementation against the pinned review in `UPSTREAM_REVIEW_2026-11-16.md`; this document does not certify a release build or hardware playback. No tests or builds were run by this implementation worker; the parent coordinates the sequential verification gate.

## Source comparison and implementation

- LastWave Native review head `7070bb2ea203e58b78ba8638caa77a5254c7cc9a`, particularly `763cbe9875`, `e087367045`, `60dbf4b97d`, `0e7e583019`, `d20b9449df`, `8842d3d1de`, `68992a8018`, `6db7b99bb2`; AETHER release/head `d952c18c57849f8a150373fa2b6acaa7cc5538e2` supplied behavior evidence. Existing third-party notices remain intact. These changes independently adapt behavior to Cosmotune's Kotlin/Media3/JVM architecture; no Euthopiar or LastWave Desktop source was copied.
- `YouTubeRequestPolicy` filters DRC formats only when a non-DRC rendition exists for the same audio-track ID, including URL-encoded `xtags` evidence. DRC-only responses lose original-rendition loudness metadata. InnerTubeX, the catalogue request client and NewPipe share this bounded interceptor. NewPipe excludes explicitly dubbed/descriptive/secondary audio and prioritizes non-DRC original/unknown audio. Resolver loudness caches remove stale metadata when a fresh rendition does not provide it.
- Android normalization no longer applies the YouTube counterpart's loudness to substitute/upgraded masters. The existing single per-player DSP stage and limiter remain; there is no added session effect or speculative Dolby makeup gain. Desktop already separated YouTube metadata from library measurements.
- `TrackMatcher` and `JioSaavnMatcher` retain explicit recording-language labels in track and release titles, alongside existing reprise/remix/clean-explicit and runtime checks. A language label is identity, while ordinary `From ...` film packaging remains compatible. Unlabelled recordings cannot have their language proved from title/duration alone.
- Shared `PlaybackStartPolicy` defines Fast start (existing default), Best quality first, and No automatic upgrades. Android and desktop persist the same enum contract. Best-first waits up to 20 seconds for competing offers and retains a usable completed offer at the deadline; it does not silently discard one because a sibling stalls. Automatic upgrade scheduling respects the policy; explicit Android manual upgrade remains available. Android next-track source preloads include slower sources when best-first is chosen; desktop upcoming decks now use the same selected policy as immediate playback. Existing pinned stream/cache identity remains the authority for bytes already being filled.
- Desktop automatic upgrades additionally require matching decoded durations and buffered replacement audio, retain the old decoder on failure, reject an offer after its original track instance/seek changes, and preserve current paused state at the audio-thread handover. The existing Android upgrade audition/revert and crossfade guards remain. Automatic acoustic alignment is still disabled.
- `FlacTiming` converts MP4 ticks to the exact, bounded 36-bit FLAC STREAMINFO sample count, rejects missing/fractional/overflowing timing, and avoids multiplication overflow. Both manifest assemblers use it. Both sample-table parsers now bound optional FullBox fields and trun records to their own boxes and require sample ranges to lie within mdat payloads. Existing v0/v1 mdhd/tkhd/tfdt offsets were already correct; regression fixtures lock that behavior down.
- Download spatial badges now require Dolby codec evidence from delivered bytes. A claimed Dolby/Atmos tier over AAC becomes AAC; unknown bytes get no spatial badge. E-AC-3 proves Dolby encoding, but a generic DOLBY badge is not a JOC/object-rendering or lossless assertion.
- Provider package startup failures now reach the existing observable errors flow. Repeated temporary failures back off from 15 to 120 seconds without changing enable choices or deleting credentials. Failed runtimes retry periodically; Android network return requests recovery. The shared provider card has a working Try again action. Authentication/verification failures remain separate. Ordinary HTTP add-ons were already lazy/stateless per-request clients rather than permanently excluded failed startup instances.
- Locale recovery retries read-only InnerTube endpoints at most twice, only for explicit rejected language/country diagnostics, omitting only the rejected request field. It never rewrites discovery region/language preferences, rotates credentials, replays account writes, or replaces explicit regional choices with detected country. JSON response inspection and replay bodies are bounded to 4 MiB.
- `LosslessOutput.addonEligible` names the source-gating rule explicitly. Accepted LDAC/LHDC/other high-bitrate Bluetooth families remain eligibility only; existing measured codec/output telemetry supplies quality claims.

## USB/native audit

Cosmotune's `DefaultDirectAudioOutput` deliberately reports inactive and falls back to AudioTrack; there is no active userspace UAC clock/feedback transport to patch. Importing LastWave's clock-interface JNI code would create a new unvalidated transport, so it was not done. The bundled FFmpeg scalar conversions already use the correct 128/32768/2147483648 divisors and clamp S16 output; no double volume scaling or transplanted JNI scratch buffers were introduced. USB descriptor discovery remains a probe, not evidence of active direct output.

Fixtures cover DRC/original offers, DRC-only normalization metadata, bounded locale requests with unchanged original inputs, language/reprise recording identity, exact FLAC timing, spatial labels from bytes, startup failure credential retention, circuit delays, deadline retention, and v1/truncated FullBox sample tables. They do not establish physical DAC clock correctness, Bluetooth codec negotiation, audible gain equality, JOC object rendering, or seamless upgrades across real recordings and hardware clocks. Physical Android Media3 and desktop decoder/output checks remain required; no live provider account, DAC, Bluetooth route, or audible playback was exercised here.
