# Podio source research

Scope: an account-free Radio / Podcasts mode in Cosmotune 1.0.7. Research is separate from integration and live playback evidence; a project's advertised platform coverage is not a playback result.

## Current coverage, 1.0.9 / 1.0.10

The research below records the original source review. Published [1.0.9](releases/1.0.9.md) now adds NASA GIBS satellite tiles, city-level zoom and ring selection, up to 3,000 directory results, disclosed approximate station locations and bundled extra public stations. Station pages show local time, Open-Meteo weather, credited Wikimedia photographs and nearby Wikipedia articles. Podcasts open on regional charts with genre chips and language search. Native phone/desktop layouts, mode sidebars and the live-station bar were rebuilt; dedicated TV/Wear/browser Podio UI remains pending.

[1.0.10](releases/1.0.10.md) is published; its release build completed successfully. Those installers retain public radio/RSS coverage and precede the podcast additions described below. See [remaining work](PENDING_WORK.md) and [live websites](LIVE_WEBSITES.md).

## Source additions after 1.0.10

The following additions require a new app build; the published 1.0.10 installers do not acquire them from a documentation update.

- **Public YouTube Music podcasts:** show cards from anonymous podcast home/search, show pages and episode continuations. The implementation follows the public response shapes also identified in the [pinned LastWave Native review](https://github.com/Clash-Projects/LastWave-Native/tree/bc8f586b96adf91c5c28958f3a8db4bf2d127590); it uses Cosmotune's shared InnerTube client and existing native stream resolver. Browse/search omit account Cookie/Authorization headers. Playback retains a `podio:episode:youtube:` identity; only the resolver boundary receives the raw video ID. A YouTube watch page is never passed to the audio decoder as an enclosure. Premium/private/unavailable episodes still depend on YouTube's actual access response; no new paid-only access is established.
- **Publisher archives:** RSS/Atom `rel=next` links load older episodes on demand, retain root-feed GUID identities, deduplicate repeated entries and stop page cycles. A failed older-page request retains the current list and offers a retry. The reader remains bounded to 8 MiB and 1,000 entries per page, and 100 archive pages per browsing session; a publisher that exposes no older-feed link does not gain a guessed archive endpoint.
- **OPML interchange:** Android uses the system Open/Create Document picker and an explicit share sheet; desktop uses its native Open/Save dialog. Paste/clipboard interchange remains available as a fallback. Nested folders, escaped titles and UTF-8 byte-order marks are handled; imports merge rather than erase existing subscriptions, favourite stations or listening positions. RSS subscriptions use normal `type=rss`/`xmlUrl` outlines; YouTube show bookmarks use `type=link`/`url` rather than falsely claiming to be RSS feeds. Imports are bounded to 1 MiB and 500 follows. Account synchronization is separate work.
- **Episode downloads:** finite publisher audio files and exact public YouTube episodes use the existing platform download queues, with progress, cancellation/retry and a Downloaded episodes view. The new routes bypass music-provider matching; a cancellable 64 KiB publisher range probe uses actual container signatures before falling back to Content-Type/URL information. Delivered-file inspection retains the existing protection against HTML/error bodies and false quality claims. Playback uses the saved file with the same Podio episode/resume identity. Android filenames include an episode-ID hash so repeated titles cannot adopt a different episode's file. Exported episodes go into Podcasts/Cosmotune (desktop: the user's Podcasts/Cosmotune folder), and Android marks them as podcasts instead of music to avoid ordinary local music scans re-importing them under a music identity. Live radio is not an episode download. Publisher HLS-only feeds and containers the destination cannot store remain separate format work; this is not a universal website downloader.
- **Background resume:** Android's media service and the desktop playback engine own episode-position recording. Positions flush on episode changes/pauses/stops, and the visible page shows Resume/Played status. Dismissing the Podio page no longer stops saving progress. Library instances for the same file share synchronized state so playback updates cannot erase a new follow/import.
- **Sleep timer:** Podio exposes the existing Android/desktop background timer with 15/30/45/60-minute presets, cancellation and end-of-episode mode. The timer remains active when the Podio page is dismissed.

`PodioLibraryToolsTest` checks archive links/cycles, stable episode identities, failed-page retention, nested OPML and concurrent library/progress ownership. `YouTubePodcastsTest` checks show/episode parsing, opaque continuations and the dedicated spoken-audio route. `PodioDownloadsTest` checks publisher container signatures, the bounded cancellable range probe, offline identity and bounded OPML files; `PodioDownloadTest` transfers an actual M4A fixture into a disposable folder and passes it to the native decoder. `PodioToolsInteractionTest` exercises import/export/share host callbacks, resume, older episodes, download/offline controls and timer actions on the real shared page. `PodioYouTubePlaybackLiveTest` is an explicitly opt-in public lookup/native-decode check; fixture or compilation success must not be reported as that live playback result. The Android route test is in `PodioAndroidTest` and still needs device/emulator execution for the new route. Native file-picker/share dialogs also need a platform walkthrough; their callback tests do not operate the OS dialog.

The public YouTube live check passed on Windows on 28 October 2026: anonymous discovery opened Lex Fridman Podcast, selected [episode #503](https://www.youtube.com/watch?v=ZAzWPE9CItg) and decoded 45,456 actual Opus samples through the native Podio route. Its playing identity remained `podio:episode:youtube:ZAzWPE9CItg`, with source `podio:youtube` and no pending music-source substitution. This is a short decode result for that public episode, not a complete-episode, protected-catalogue or macOS/Linux/Android listening claim.

The 1.0.11 source also adds a dedicated TV page using existing D-pad components and the TV media service: public station/podcast discovery, saved stations/follows, episode/archive lists and resume. A browser Podio route has radio, public RSS directory/feed discovery, anonymous YouTube podcast browsing, saved stations/follows, episode resume/Played labels and a persistent player bar. Browser audio retains Podio identities in a separate lane; selecting music stops Podio, while selecting Podio cancels pending music loads and retains the music queue/resume position. Browser feeds and streams require HTTPS, browser-supported formats and appropriate publisher CORS access; native-only map/download/OPML details are not claimed as browser parity.

Browser typechecking and five tests across three files passed on 28 October 2026, including real-page station saving, opening a show, episode playback identity and persistent controls. A separate public network probe verified Radio Browser `Access-Control-Allow-Origin: *`, a BBC World Service HTTPS MP3 response with 2,800 actual bytes, Apple search and The Daily feed CORS access (67 publisher entries), and 4,096 bytes from an HTTP 206 publisher MP3 enclosure. This is catalogue/CORS/media delivery evidence, not a full listening session or proof that every publisher supports browsers. Native TV compilation and remote/device walkthroughs require separate validation.

Wear companion discovery, broader independent directories, additional enclosure/archive formats, account synchronization and remaining physical-device execution are still pending.

## Radio sources

[Radio Browser](https://api.radio-browser.info/) documents a free, open-source station directory with geographic coordinates, languages, country/genre filters and stream URLs. Clients should discover/randomize mirrors, fail over, identify their user agent and report station play clicks. This supports a Radio Garden-inspired geographic interface without relying on Radio Garden's undocumented internal endpoints.

## Coverage rules

- A searchable show is not automatically a playable episode. Playback uses a publisher's actual enclosure or a separately tested source adapter.
- Public feeds commonly underlie listings in multiple podcast apps; these are deduplicated by feed identity rather than advertised as different audio providers.
- No listener login is required for the public radio/directory/feed paths. No universal access to paid-only shows has been established.
- Do not import third-party account cookies, API secrets, decompiled application binaries or DRM tools as a dependency of Podio.
- Keep catalogue access, stream resolution, playback verification and unimplemented ideas distinct in the feature tracker.

## Implemented in Podio

Android phone/tablet and desktop have the same Radio / Podcasts page. Radio includes a draggable, zoomable globe with Natural Earth public-domain land outlines, country/language/name search, a station list and local favourites. The globe samples up to 1,200 popular geolocated stations; directory search reaches beyond that sample. Since 1.0.8, each list request returns up to 1,000 stations, language values are normalized to lowercase, and the map can expand and zoom up to 8×. Filtering retains the selected country; Clear returns to worldwide browsing. Stations without coordinates remain playable from the list.

The published 1.0.10 podcast baseline combines Apple/iTunes and fyyd, deduplicates feed URLs and tolerates one directory failing. Open a publisher RSS/Atom feed or paste a Spotify show/episode link to find matching public RSS audio. A Spotify link is not itself an audio provider. Following, station favourites and episode positions are stored locally. Episode playback supports resume, seeking, back 15 seconds and speed selection. RSS parsing is bounded to 8 MiB and 1,000 entries; Spotify metadata lookup reads the latest 100 entries. The newer source adds the YouTube discovery/native route, publisher archive links, downloads, OPML and timer controls described above; account sync remains separate work.

Playback uses the existing native desktop engine or Android Media3 service, including background controls. Radio has a live indicator rather than a finite song scrubber. Podcast/radio IDs bypass song-video searches, music recommendations, beat analysis and music scrobbling. Android permits HTTP public radio/feed enclosures because many stations have no HTTPS stream; provider-package transport keeps its separate HTTPS checks.

Spoken-audio speed is temporary: changing to a music item restores the saved music speed, while browsing another page does not change the current episode's rate. Podio is also excluded from song-lyrics requests, YouTube listening-history reporting, music preference training and Android ListenBrainz submissions. Public RSS audio is not sent through the music quality-upgrade search.

The Spotify metadata adapter uses its own anonymous, memory-only web session and never imports browser/account cookies. Its web-client operation hashes and bootstrap can change upstream. A match requires the same normalized show name and overlapping episode identity; an episode link also requires the same title and compatible duration. Namesakes or mismatched recordings are rejected. If there is no public feed, the app explains that Spotify-only audio is unsupported. No direct Spotify stream resolver, music endpoint, licence/key request or protected-format decoder is added.

## Verification evidence

- Live Radio Browser, Apple and fyyd requests returned real station/show metadata on 2026-10-26.
- The inspected Votify revision was executed with `sp_dc=None` for the Lex Fridman show (`2MAi0BvDc6GTFvKFPXnkCL`). Anonymous show/episode metadata and CDN resolution worked. Opening audio bytes decoded, but further checks at 120 and 3,600 seconds failed without a key. Android likewise rejected the protected track. The initial short decode is explicitly **not** evidence of full Spotify playback; the attempted direct resolver and experimental format workaround were removed before release.
- Radio MP3, direct publisher RSS MP3, and publisher RSS matched from a Spotify link passed Cosmotune's actual native desktop decoder (44,928 samples each). No direct Spotify AAC playback claim remains.
- `PodioCatalogueTest` covers feed identity/duration, XML and URL rejection, radio failover, directory deduplication/partial failure, saved library data, and Spotify-to-RSS matching with rejection of timing mismatches. `SpotifyPublicPodcastsTest` checks anonymous metadata requests, exact JSON encoding, and absence of audio-resolution/licence calls. `PodioInteractionTest` exercises the actual shared page, playback callbacks, favourites/following and phone link entry.
- `PodioAndroidTest` passed all three tests on the dedicated Android API 36 emulator in 20.669 seconds: RSS parsing/entity rejection, real Media3 publisher playback, Spotify-link-to-RSS playback, rendered audio after seeking to 60 seconds, and the actual media service restoring the saved 1.25× music rate after a 1.5× podcast. This is emulator evidence, not a physical-device listening claim.

The other projects above were reviewed as source; they were not all executed or imported. No working universal account-free source for Spotify-only, paid Spotify, Pocket FM, Patreon or other subscription catalogues was verified. Spotify links work only when matching public publisher RSS audio is found. TV, Wear OS and browser-specific Podio interfaces remain outside this first implementation.
