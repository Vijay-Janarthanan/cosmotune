# Desktop direct output and fullscreen visuals

The new optional **Prefer direct device output** setting is off by default. Normal system output remains available. A selected direct route must actually accept the source sample rate, channel layout and encoding; an advertised high-resolution source tag never establishes the output format.

| Platform | Opt-in path | Negotiation and fallback |
| --- | --- | --- |
| Windows | WASAPI exclusive | `IsFormatSupported` and successful exclusive `Initialize`; float32, integer32, packed24 and integer16 at the original rate/layout are tried. Driver buffer alignment is handled. If unavailable or busy, use WASAPI shared, then Java Sound if native output is unavailable. Device rerouting may return to shared mode and the readout updates. |
| macOS | CoreAudio AudioQueue with hog ownership | Acquires and reads back device ownership, requests and reads back the source nominal sample rate, then creates an actual float32 queue on that device. Restores the previous rate and releases ownership on close/failure. Unsupported/busy devices fall back to Java Sound. |
| Linux | ALSA `hw:` output | Enumerates real playback hardware from `/proc/asound/pcm`, disables software resampling, and reads back the actual rate, channels and encoding after opening. A device occupied by PipeWire or another client falls back to the ordinary system route. This does not reconfigure or stop PipeWire. |

These are **direct, unconfirmed** paths in the fidelity readout. None is labelled confirmed bit-perfect solely because the device is held. Volume, loudness normalization, equalizer, spatial effects, time stretching and crossfades still change samples. The decoder uses float32, which cannot preserve every bit of an integer source wider than 24 bits. The readout identifies that limit. DSD remains converted to PCM; native DSD and DoP are **not enabled** because the existing decoder/transport path has no untouched DSD frames to pass through.

The implementation uses the existing JNI Windows bridge and existing JNA dependency for the OS libraries. It imports no code from the unlicensed LastWave snapshot and adds no bundled native audio engine. Source references: [WASAPI format support](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-isformatsupported), [WASAPI initialization](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-initialize), [Apple AudioQueue](https://developer.apple.com/documentation/audiotoolbox/audioqueuepropertyid), [ALSA PCM interface](https://www.alsa-project.org/alsa-doc/alsa-lib/group___p_c_m.html).

**Validation scope:** the Windows C++ bridge compiles. `DesktopDirectOutputTest` covers actual-acceptance selection, exact 16/24-bit PCM reconstruction, 32-bit clipping, direct/fidelity reporting and bounded visual sampling. Platform Kotlin compilation and test results are tracked with the release checks. No DAC was seized during development while the user's app was playing. macOS/Linux native calls, device unplugging and real DAC precision still require physical execution; compilation is not evidence of successful output on those devices.

The player also offers **Visuals**: a separate fullscreen Artwork, Pulse or Waveform window, closed with Escape or Close. Pulse and Waveform are original scenes driven by local post-processing PCM and current volume; sampling is dormant while no visual window observes it. They download no artwork packs or Workshop content. These visuals do not enable audio effects or change playback.
