# Local library tools for 1.0.4 (in development)

Listening tools → Backup & transfer now exports the current queue's local files or the local library to UTF-8 M3U8. Android uses its document chooser with the playlist MIME type; desktop uses the native save dialog. Queue order and repeated tracks survive. A queue track can resolve a saved local file through its exact source-qualified recording ID in the library; no title-based substitute is chosen.

Only readable absolute file paths or file URIs are exported. Online-only recordings, missing files, signed HTTP addresses and device-only content-provider links are skipped and counted. Metadata cannot inject extra playlist lines. Exports are limited to 10,000 tracks and 4 MiB, include local file locations and do not copy audio or carry credentials. Moving a playlist to another device requires copying the music and adjusting its locations. This is a local playlist export, separate from listening metadata backup and from linked-playlist synchronization.

Two format/filesystem tests pass Unicode filenames/metadata, duration parsing, order/duplicates, directive injection protection, skipped counts and limits. An actual Compose interaction passes queue-to-download lookup and platform chooser handoff; Android production and desktop Kotlin compile. The real OS chooser and another player's import still need a walkthrough. Tag editing, duplicate/repair review, quality upgrades and linked synchronization remain separate tracker work.

Desktop save operations now retain the expected metadata-file extension and publish through an adjacent temporary file, fsync and atomic replacement where supported. A referenced audio file or local manifest cannot be selected as its own M3U8 export destination. Two additional filesystem/failure-injection checks pass preserving an existing backup on interrupted output, cleaning partial files, retaining the correct suffix and preventing source audio/manifest replacement. Desktop compilation passes. The interrupted local run was replaced by a successful bounded, in-process build.

## Library review in progress

Listening tools now has a Library review tab on both native hosts. Its bounded read-only scan checks local filesystem locations and Android content-provider grants, distinguishes missing, empty and permission-restricted files, and detects container signatures independently of filename extensions. Filters cover measured format, problem state and title/artist/album/source text. This is header evidence, not decoded bitrate, a spectral audit or proof of the original master.

Duplicate groups distinguish aliases of one canonical file, SHA-256-identical files and matching metadata candidates. Byte comparisons stream 64 KiB chunks, skip files outside the explicit default 2 GiB comparison budget, check size/modification/identity after reading, and honor cancellation. Different editions and encodings are never automatically merged. No audio is removed or replaced by this review. Reports explicitly contain local locations and are capped at 16 MiB; remote stream addresses and error details are excluded.

Saved-session repair previews use readable local copies with the exact source-qualified recording ID. Apply checks the original entries and replacement availability again before one atomic store update; duplicate queue entries, position, shuffle/repeat and other metadata survive. This repairs session references, not the download registry or filesystem. Updates now read the latest durable state under a shared path lock, use unique adjacent temporary files and preserve the original on failure. A preview cannot overwrite a correction saved by another open window.

The final focused run passed **29 tests, zero failures/errors/skips**: five audit/repair checks, eleven store checks, two network checks, four M3U8/atomic-output checks and seven actual Compose interactions. The new UI scan/export/preview/apply test renders a screenshot at `uiTests/build/reports/listening-ui/library-review.png`. Android release/debug/test-source and desktop compilation passed at the preceding checkpoint; the subsequent minified Android rebuild includes the latest store/availability safeguards. Its actual startup/mode-switch checks are still pending. Tag editing, actual duplicate merging/removal, moved-file fingerprint reconciliation, decoder-based quality audits, lossless replacement, genre columns and linked playlists remain outstanding.
