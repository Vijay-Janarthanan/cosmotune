# Cosmotune for Android TV (1.0.4 work in progress)

This separate TV package reuses Cosmotune playback/account/data code with a D-pad interface, profiles/PINs, USB music, setup and display preferences. Phone/watch IDs and data remain separate. The module is included when an Android SDK is available. It has not been released; production packaging and device checks are in progress.

Sources and adaptations are recorded in UPSTREAM_IMPORT.json and the root NOTICE.md/FORK.md. The JSON index retains original SHA256 values and source-record IDs; exact upstream links live in the central attribution ledger. Original extra font/banner binaries and the disabled legacy HTTP cookie-transfer server are excluded. Existing Cosmotune fonts plus system sans/monospace families and a vector brand banner are used. Sign-in uses the native TV WebView. Settings → Connections → Phone remote opens a paired browser controller for playback, seeking, volume and music search. Opening account controls or changing profiles stops the remote; a locked profile must be verified before a new session can start. Pairing never transfers account cookies.

Twenty-three TV PIN/throttle/profile/QR/effect tests and signed release assembly pass. All four packages pass entry/update-family/ABI/certificate/model checks. A landscape phone AVD passed D-pad onboarding/public Home/settings, rendered QR decoding and real paired-browser music search/playback/seek/volume/pause. Opening account controls revoked the session and disabled the browser controls. A UI-automation capture process error is recorded separately in docs/TV_REVIEW.md; no physical TV/display/USB/spatial/refresh-rate claim is made. Spatial processing is off by default and follows the live playback session only when enabled. The public version and release key come from the root 1.0.4 configuration. TV APKs use `CosmotuneTV-<version>-android-<ABI>.apk`; the updater rejects phone/watch packages and incompatible TV splits. Final full-tracker regression/packaging remains required before publication.
