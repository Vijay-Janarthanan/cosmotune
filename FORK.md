- The backend now builds `cosmotune://party/...` deep links and its page text says Cosmotune, but none of that Go was compiled or tested (no Go toolchain on the build machine): a human has to run `go build` and `go test` in `backend/` before relying on it. - Names and ids (Task 5): what people read, what the app files itself under and what it announces to the system is Cosmotune's own (`ForkGuardTest` checks it). Kept on purpose, because they are internal and renaming them would make every upstream merge conflict: the packages `com.music.bitchord` and `namespace`, class names such as `BitChordApplication` and `BitChordIcons`, the `bitchord.*` system and Gradle properties, the `BITCHORD_*` environment variables, the `bitchord://` internal stream scheme, `bitchord_window` / `bitchord_analysis` / `bitchord_smtc` native libraries, `bitchord-app.jar`, `Theme.BitChord`, resource keys such as `widget_open_bitchord`, log tags (`"BitChord"`), the `com.music.bitchord` MP4 tag namespace in `Mp4Tagger.kt`, and the backup tag in `Backup.kt`.
